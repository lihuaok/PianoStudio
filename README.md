# 🎹 Piano Studio · 世界级钢琴教学软件

从零基础到完整演奏的钢琴学习系统。内置 **《致爱丽丝》** 完整乐谱（105 小节，逐音精确）与分章精讲，
配套六级课程体系、互动乐理实验室、实时弹奏评测与跨设备进度同步。

## 一、快速开始

```bash
npm install          # 安装依赖
npm run build        # 构建前端（输出到 dist/）
npm run server       # 启动服务（前端 + 同步 API，单进程）
# 打开 http://localhost:8791
```

### 端口

默认端口 **8791**（绑定 `0.0.0.0`，同一 WiFi 下手机/平板可直接访问 `本机IP:8791`）。

可通过环境变量覆盖，避免与本机其它项目冲突：

```bash
PORT=8890 npm run server          # Windows PowerShell
PORT=8890 npm run server          # bash
```

> 本机端口占用情况（避免冲突参考）：
> 8000/8443/9200/18000 已被 C-Lodop 占用；
> 8001、8020、8091、8123、5173、5088 供其它项目使用；
> **8791 未被任何其它项目占用**。
> Vite 开发服务器另用 5178（已配置 `/api` 代理指向 8791）。

开发模式（前端热更新 + 代理同步接口）：

```bash
npm run server       # 终端 1：后端 8791
npm run dev          # 终端 2：Vite 5178（已配置 /api 代理）
```

> **注意**：本项目依赖 esbuild / rollup 的 Windows 平台二进制。若在受限沙箱中安装，
> 需显式补装（npm 的 postinstall 会被沙箱拦截）：
> ```bash
> npm install --no-save @esbuild/win32-x64 @rollup/rollup-win32-x64-msvc
> ```
> ⚠️ 两个包必须**一起安装**，分开装会互相 `remove` 导致构建失败。

## 二、核心功能

### 🎹 自动演奏（完整演奏《致爱丽丝》全曲）

一键完整演奏 **125 小节 / 930 音**（1041 个发声声部）的全曲（ABACA 回旋曲式，默认 126 八分/分 ≈ ♩=63，约 2 分 58 秒），**不是只弹开头动机**。

| 能力 | 说明 |
|---|---|
| **全曲覆盖** | 弱起 + 主部三次再现 + 插部一（F 大调舞蹈）+ 插部二（C 段高潮）+ 尾声，左右手双声部，含反复记号、倚音、三连音、8va 段落 |
| **乐谱权威性** | 数据逐音对齐 Mutopia 官方 MIDI（Breitkopf & Härtel 1888 底本）：右手 517/517、左手 388/388 **逐音全等**（位置·时值·音高），见 `tools/score-verify-midi.mjs` |
| **音源** | **默认真实钢琴采样**：Salamander Grand Piano V3（CC BY 3.0）三层力度录音（p / mf / f），每 3 个半音一个采样点 + 变速补全，见 `public/samples/` |
| **音色（回退链路）** | 采样未就绪时由内置合成接管：FM 电钢琴 / 柔和大钢琴 / 三角钢琴 / 明亮 / 柔和 / 音乐厅平衡六种预设，保证"点了就有声" |
| **采样标定** | 三层录音响度差由 `manifest.json` 的层增益抵消，使所有层共用一条力度曲线 → 跨层听不出台阶；标定脚本 `tools/sample-calibrate.mjs` |
| **每个采样的四处坑** | URL 的 `#` 必须编码（否则升号音静默 404）、跳过 mp3 编码填充静音、解码后按音高裁剪（原采样长 22 秒 / 解码近 500MB）、层增益标定 |
| **每声部低通** | 合成回退链路上：截止频率 = 基频 × 系数且随力度开合，从根上消掉加性合成那种刀片似的亮（实测 4kHz+ 能量占比 0.01%） |
| **四级包络** | 线性起音（≥4ms，杜绝爆音）→ 衰减到延持电平 → 按键释放（制音器）→ 抬起；全程无稳态平台 |
| **末级软限幅** | tanh 软削波（4× 过采样）接在**音量之后**，越响越饱和而非硬切；实测整曲播放峰值 0.86、0 次满幅 |
| **力度诠释** | 没有 dynamic 标记的机读乐谱 → 由曲式基调 × 乐句拱形 × 拍点重音 × 旋律突出 × 装饰音轻奏推导，动态范围 0.19–0.97 |
| **踏板** | 按左手和声签名变化自动换踏板（99 段）；密集十六分段落自动降级为**半踏板**避免半音糊成一片；曲末收束长踏板 |
| **踏板余韵** | 采样音源下不人为截断，让录音自然衰减（最多 5.5s），制音器在踏板抬起时统一落下 |
| **弹性速度** | 乐句内 ±4.5% 的时间起伏，时间轴严格保持单调（可复现，固定种子） |
| **播放控制** | 播放 / 暂停 / 继续 / 停止、进度条任意跳转、±3 小节步进、8 段结构卡跳转 |
| **实时参数** | 音量、速度（60–160 八分/分，实时生效且撤销已排程的旧速度音）、混响、踏板、共鸣（合成时）、音源切换 |
| **琴键联动** | 正在发声的音实时点亮屏幕键盘（可直接点键盘试听，同样走采样音源） |
| **可验证性** | `tools/autoplay-tone-check.mjs` 在真实浏览器播整曲并在最终输出取样，量化峰值 / RMS / 静音帧 / 频谱 / 命中率；`tools/diag-score.mjs` 核对是否漏音 |

实现取舍、时序精度保证与可扩展方向见页面底部说明。

## 三、技术实现

### 乐谱来源与准确性（重要）

《致爱丽丝》的乐谱数据**不是手工抄写**的。流程如下：

```
Mutopia Project (Mutopia-2015/08/18-931, 底本 Breitkopf & Härtel 1888, 公有领域)
        │  fur_elise.ly  （LilyPond 权威雕版源）
        ▼
tools/lilypond-to-score.mjs   自研 LilyPond 解析器
        │  小节归属由「累计时值 ÷ 拍号」计算（源码中无显式小节线）
        ▼
src/data/furElise.json         766 音符 / 105 小节
```

**为什么不用现成的机读乐谱？**
调研发现网络上多个「独立来源」（ABC / MusicXML / PDF / piano.org）实际上**同源且有相同错误**：
都把第 2 小节的附点四分 A4 拆成了「八分 + 十六分休止 + 假琶音」，并把左手的 A2-E3-A3 琶音错移到下一小节。
详见 `tools/scoredata/` 与调研记录。Mutopia 雕版来自不同的书目传承（Breitkopf 1888），可作为独立校勘本。

### 关键算法

| 模块 | 位置 | 说明 |
|---|---|---|
| 钢琴合成 | `src/audio/audioEngine.ts` | 8 分音泛音列（含非谐性修正）+ 槌击噪声 + ADSR + 程序生成卷积混响，零采样依赖 |
| 节拍器 | 同上 | 前瞻式调度，避免主线程卡顿导致的节奏抖动 |
| 评测对齐 | `src/core/evaluator.ts` | 动态规划（滚动数组）求解最优匹配，代价函数含音高/时间/漏音/多余音 |
| 音高检测 | `src/core/input.ts` | YIN 算法（差分 → 累积均值归一化 → 绝对阈值 → 抛物线插值） |
| 谱表几何 | `src/core/score.ts` | 以「字母级绝对步数」定位，升降号**不改变字母位置**（符合真实记谱规则） |
| 进度合并 | `src/core/progress.ts` / `server/index.mjs` | 离线优先 + 防抖推送 + 服务端合并，原子写入（临时文件 + rename） |
| 演奏诠释 | `src/core/interpretation.ts` | 纯函数推导力度（曲式基调 × 乐句拱形 × 拍点 × 旋律突出 × 人性化抖动）、踏板（左手和声签名变化 + 密集段落半踏板 + 曲末收束）、乐句划分、弹性速度（保序时间扭曲） |
| 自动演奏调度 | `src/audio/autoPlayEngine.ts` | 前瞻调度（25ms / 0.35s）+ 踏板状态机；暂停/跳转/实时变速都会 `cancelFuture()` 撤销已排入音频时钟的未来音符 |
| 采样音源 | `src/audio/sampleEngine.ts` | 稀疏采样点（每 3 半音）+ 变速补全、多力度分层（层增益标定使力度曲线跨层连续）、mp3 编码延迟补偿、解码后按音高裁剪、LRU 内存预算 256MB、邻近层借用 + 合成回退 |

node tools/autoplay-tone-check.mjs     # ★ 真实浏览器播整曲并在最终输出取样：峰值/ RMS /静音帧/频谱/采样命中率

```

### `autoplay-tone-check.mjs`：把"好不好听"拆成可测的量

音色好坏是主观的，但下面这些是**客观可测**的，而它们恰好覆盖了"难听"的全部成因：

| 指标 | 实测（全曲） | 说明 |
|---|---|---|
| 输出峰值 | **0.86** | 目标 0.8–0.95。过低 = 没劲，>1 = 削波 |
| 满载帧 | **0** | 软限幅被击穿的次数，必须为 0 |
| RMS | **−24 dBFS** | 独奏钢琴的合理区间是 −26 ~ −23 |
| 静音帧占比 | **12.6%** | 乐句呼吸之外的大段无声 = 漏音 |
| 采样命中率 | **100%**（0 misses） | 未命中意味着该音落到了合成回退上 → 音色断层 |
| 4kHz+ 能量占比 | **0.07%** | 过量为"刺耳"，过少为"闷" |

它还会输出**每秒平均 RMS 的时间线**，一眼能看出哪几秒没有声音。
采样层响度差异则由 `sample-calibrate.mjs` 单独标定（见 `public/samples/README.md`）。

### `score-verify-midi.mjs`：以官方 MIDI 为金标准

自研 LilyPond 解析器的正确性不能靠"看起来对"。这个脚本用 Mutopia 官方输出的
`tools/scoredata/fur_Elise_WoO59.mid` 当金标准，做两级校验：

- **A 级（逐音全等）**：解析器折叠反复后生成的数据 ≡ 官方 MIDI，
  比对维度是「起音点 + 音高 + 时值」，按发音点分槽比对（一处错位不会让后面几百个音连锁报假错）。
  装饰音因落在 LilyPond 的有理数网格上而我们只有 1/24 四分音符刻度，放行 ±16 tick（<30ms）。
- **B 级（结构断言）**：演奏用的展开版 = 折叠版 + 各反复段的 body 副本。

它抓出并定位了这一串致命 bug（全部曾让"弹出来完全不是原曲"）：

| # | Bug | 症状 |
|---|---|---|
| 1 | `lilyAlter()` 正则只有 1 个捕获组却取了 `m[2]` | 全曲升号被吞，D♯/G♯ 退化成 D/G |
| 2 | 大写 `R`（全小节休止）被当 skip 且不推进时间 | 左手整体前移一小节 |
| 3 | `\pp` 这类无参命令吞掉后随的 `R4.` | 左手丢失整段休止 |
| 4 | tokenize 按行切分 | 跨行的 `\repeat volta 2 {…}` 连同内容被丢弃 |
| 5 | `main()` 从 `\partial` 处切 staff | 第一个反复声明被切掉 |
| 6 | Scheme 表达式 `#(ly:make-moment -1/8)` 里的字母被当音符 | 凭空多出 A3/E3/E3 |
| 7 | `<c' e'>8` 的时值写在尖括号**外**被丢弃 | 和弦退回"继承上一个音的时值"，整段提前半拍 |
| 8 | `\grace` 的时序处理错 | 倚音被排到主音**之后**，旋律凭空多出重音 |
| 9 | `\appoggiatura`（无花括号形态）被当无参命令忽略 | 倚音占满三十二分，段后全线错位 |
| 10 | `tuplet` 存成 parseStream 局部变量 + 比例写反 | 三连音缩放从未生效（×3/2 应为 ×2/3） |
| 11 | 参数后的花括号组未收进 token | `\tuplet 3/2 {…}` 的内容脱离三连音作用域 |
| 12 | `\ottava #1` 被当成音高移调 | 8va 段落整体错一个八度（8va 只影响记谱） |

> 教训：**解析器的期望值必须来自外部权威数据，而不是自己写死的数字**。
> 同一批 bug 里还有几个是"测试期望值本身写错"造成的误报。

### `autoplay-sim.mjs`：无浏览器跑完整曲

它伪造一套最小 Web Audio 环境（FakeAudioContext + 可控时钟 + 假 window），
把真实的 `AutoPlayEngine` 完整跑一遍全曲，因此能在**没有浏览器**的情况下
断言"930 个音一个不漏/不重"、"每个 tick 只调度 7 个音（证明是前瞻而非预调度）"、
"结束时刻与理论时长一致（208.4s vs 208.5s）"这类真正重要的性质。

它抓到过的真 bug：<b>弱起小节的 4 个音（beat 为负，正是最著名的开头 E–D♯）被
`indexAtBeat(0)` 跳过</b>——时间原点必须以曲首弱起为准，而不是"第 0 拍"。

`geom-test.mjs` 校验的是**记谱学规则**本身，例如：

```
✓ F5    → treble  y=  0   高音表 顶线
✓ E5    → treble  y=  5   高音表 第4间
✓ A2    → bass    y= 35   低音表 第1间
✓ G#3   → bass    y=  5   低音表 第4间（G♯不改字母位置）
```

这些校验在开发中确实抓到了 bug（低音谱表顶线常量写错，导致整表偏移三度）。

## 五、目录结构

```
src/
├── audio/         音频引擎（合成回退）、节拍器、曲目播放器、自动演奏引擎、采样音源
├── components/    钢琴键盘、五线谱渲染器
├── core/          乐理库、乐谱模型、评测引擎、输入采集、进度与同步、演奏诠释层
├── data/          课程数据、致爱丽丝乐谱数据（自动生成）
├── hooks/         useAutoPlayer（自动演奏的 React 绑定 + 采样预热）
├── pages/         八个页面（首页/课程/乐理/曲目/自动演奏/练习室/进度/设置）
└── styles/        设计系统（暗色奢华 + 琥珀/靛蓝双主色）
server/index.mjs   零依赖同步服务（Node 内置模块）
public/samples/    Salamander Grand Piano V3 采样 + manifest.json（自动演奏默认使用，缺失则回退合成）
tools/             乐谱解析器、MIDI 交叉校验与十一个校验/自查脚本（含音频客观测量与采样标定）
```
